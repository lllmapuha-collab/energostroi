## Что было сломано и что исправлено

1. **Класс `.ges-card` не был определён** в `globals.css`, хотя использовался в 8 местах
   (калькулятор, подбор, избранное, формы, страницы `o-kompanii`/`resheniya`/`uslugi`/`zayavka`).
   Карточки отображались без фона, рамки и скруглений. → Класс добавлен.

2. **Подбор: выбор варианта не подсвечивался.** Кнопка выбранного варианта получала класс
   `active`, а в CSS стилизован только `.is-active`. Визуально казалось, что «варианты не
   кликабельны». → Исправлено на `.is-active`; активное состояние ghost-кнопок усилено
   (заливка + акцентная рамка + жирный шрифт); добавлен `aria-pressed`.

3. **Каталог содержал дубли.** 337 строк → на сайте показывались 337 карточек, из которых
   194 — повторы одной модели, отличающиеся только исполнением. → Построен слой
   дедупликации; сайт показывает 143 канонических товара (см. `CATALOG_DEDUPLICATION_REPORT.md`).

4. **Бизнес-логика калькулятора жила в JSX.** → Вынесена в модуль `src/lib/economics.ts`
   с полной валидацией (пусто/ноль/отрицательное/текст/NaN/Infinity/деление на ноль) и
   покрыта unit-тестами. CAPEX и срок окупаемости не выдумываются.

5. **Форма заявки без клиентской валидации и состояний.** → Добавлен помощник
   `src/lib/lead.ts` (имя/компания/телефон/email/тип), показ ошибок под полями,
   состояние «Отправка…», защита от повторной отправки.

6. **Отсутствовал тестовый фреймворк.** → Добавлен vitest (+ jsdom, testing-library);
   51 тест по каталогу, дедупликации, калькулятору, форме, сравнению/избранному.

7. **Не было SEO-инфраструктуры.** → Добавлены `sitemap.ts` и `robots.ts`; товарные URL
   строятся из канонических товаров, дублей slug/URL = 0.

8. **Удалён мёртвый код** `products.seed.backup.ts` (ломал type-check, нигде не использовался).
